# idle-lineage-class — lostshin 整合修改版

以秋玥（shines871）的《天堂》放置同人遊戲為基礎，整合 pp771007 加掛，並調整介面、隊伍管理、能力說明、倉庫與存檔操作。

**本版主要差異：可調整的三欄介面、可查看隊友裝備與能力來源、可縮放的雙欄倉庫，以及隊友進度、DPS、增益與 AC 顯示修正。** 原版的職業、地圖、裝備與戰鬥系統仍是遊戲基礎。

[直接遊玩 lostshin 版](https://lostshin.github.io/idle-lineage-class/) · [原版遊戲](https://shines871.github.io/idle-lineage-class/) · [pp771007 加掛版](https://pp771007.github.io/idle-lineage-class/) · [原始碼](https://github.com/lostshin/idle-lineage-class)

### 本版已修正的問題

- **AC 顯示不一致**：左上角現在會計入隊友防禦光環與疾病狀態，與裝備區及實戰使用的 AC 一致。例如自身 AC −58、隊友提供大地的祝福時，顯示 −65。
- **能力與套裝說明混入衍生值**：套裝簡述依原生直接效果整理。歐林西瑪兩件套顯示「六項屬性各＋1、AC－5、HP＋50」；敏捷或體質衍生的其他差值留在能力來源查詢。
- **隊友經驗遺失或重複結算**：擊殺後即時更新隊友進度，回村只結算受僱期間增量；來源寫入失敗時保留待領資料供重試。
- **增益提前消失或錯誤恢復**：調整回村刷新、效果到期及重新施放流程，避免舊存檔倒數覆蓋隊友現有增益；普通加速術會影響寵物與召喚物的實際速度。
- **DPS 出現假傷害**：怪物逃離、瞬移或被新怪取代時，不再把消失視為 HP 歸零；修正寵物額外攻擊與持續傷害的歸屬及重複計算。
- **施法日誌被普攻洗掉**：各來源分別保留歷史，並保留向上捲動時的閱讀位置。
- **強化後無法繼續或誤耗卷軸**：視窗保留結果；堆疊拆分後追蹤實際被強化的物品，爆裝、缺卷軸或達上限時停止不可執行的操作。
- **介面重疊與懸浮跳位**：修正窄側欄的名稱／控制項擠壓、裝備格超出背景、縮放後座標偏移，以及提示定時更新時跳到其他物品的問題。
- **倉庫操作狀態遺失**：交易後保留兩側捲動位置；寫入失敗保留本次數量設定供重試，調整尺寸不會重建輸入框打斷編輯。
- **關頁後沒有離線結算**：恢復符合條件的關頁離線收益；沒有收益時，系統日誌會說明阻擋原因。

## 啟動遊戲

可直接使用前面的線上遊玩連結。本機遊玩不需要 npm、建置流程或後端服務；若使用 HTTP，先安裝 Python 3，在專案根目錄執行：

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

開啟 [本機遊戲入口](http://127.0.0.1:8000/index.html)，按「開始遊戲」。按 `Ctrl+C` 關閉伺服器。

也可以直接用瀏覽器開啟 `index.html`。線上網站、本機 HTTP 與 `file:` 的儲存各自獨立；不同網域、連接埠、瀏覽器或使用者設定檔，也不會自動共用進度。

目前以桌機操作與窄側欄為主要維護範圍；這一輪驗收未包含手機、平板或實際桌面安裝版。

## 倉庫操作

1. 開啟倉庫，左右分別顯示背包與倉庫，可各自上下捲動。
2. 直接點物品名稱或圖示，轉移整疊。
3. 要轉移部分數量，先點該列右側數量，輸入正整數且不得超過持有量。
4. 按 `Enter` 完成數量設定，再點該物品名稱或圖示轉移；按 `Escape` 取消編輯。

交易成功後清除該物品的本次數量設定；交易失敗時保留供重試。搜尋或切換分類會回到清單頂端。視窗可拖動、調整尺寸，本次工作階段重開會保留調整結果，重新載入則回到預設尺寸。

## 存檔與帳號搬移

網頁版進度保存在目前瀏覽器的本機儲存，不會因開啟另一個版本的網站自動搬移，也沒有自動雲端帳號同步。

搬移前先從來源版本匯出備份，保留原始檔，再於本版操作：

1. 回到角色選擇頁，讓其他正在遊玩的角色分頁也回到選角頁。
2. 按「匯入帳號」，選擇本版帳號檔、支援的加掛版完整備份，或一次多選舊版角色檔；帳號檔要單獨匯入。
3. 檢查預覽中的角色位置、相同角色更新與不同角色的衝突選擇。
4. 確認共用資料的還原範圍，再按「確認匯入」。

帳號匯出包含八格角色，以及支援的一般／經典倉庫、圖鑑、寵物、血盟／城堡、龍鑽等共用進度；不搬移外掛開關、裝置縮放與工作階段鎖定。匯入的共用資料可能影響未匯入的現有角色，請以預覽內容為準。

網頁版與安裝版存檔格式分開，不能交互匯入。程式保留既有格式與寫入失敗回復流程；若畫面回報回復失敗，保留匯入檔並重新載入確認資料。

## 離線收益如何生效

真正關閉頁面後重開，符合條件時依同圖實戰樣本的 **70% 效率**結算，最短 1 分鐘、最多 12 小時。離開前需在可離線狩獵地圖累積至少 15 秒、3 隻擊殺的同圖樣本，且最近 5 分鐘仍有擊殺；擔任傭兵中的角色不適用。

切換分頁或縮小但仍保留遊戲頁面時，走原本的戰鬥補跑流程，與關頁離線收益分開。沒有看到離線收益時，先查看系統日誌中的原因。

## 修改與本地檢查

本專案使用原生 JavaScript，共用全域狀態，沒有 `package.json` 或建置流程。`index.html` 決定 script 載入順序。

本地檢查需要 Python 3、Node.js 與 Git，不需要 Ego。在專案根目錄執行：

```bash
python3 scripts/check-local.py
```

工具檢查 JavaScript／測試語法、git 差異空白、資源快取 SHA、46 個鏡像加掛檔 SHA，以及全部 `tests/*.integration.js`。目前共有九支整合測試，合計顯示 `13/13 passed`；任一失敗會回傳非零結束碼。Node 整合測試不能代替瀏覽器排版與互動驗收。

修改前端 JS／CSS 後，更新資源快取版本再檢查：

```bash
python3 scripts/update-cache.py
python3 scripts/check-local.py
```

鏡像加掛檔與 `sw.js` 保留來源內容，整合差異放在專案模組。修改時沿用現有 script 順序。

## 執行瀏覽器 E2E

需要 Python 3、`ego-browser` CLI 與可連線的 Ego。runner 自行啟動 HTTP 測試伺服器，測試只使用合成角色與隔離儲存。

查看 suite 與參數：

```bash
python3 tests/run-rwd.py --help
```

第一次執行單一 suite，保留測試空間：

```bash
python3 tests/run-rwd.py --suite rwd --protocol http --desktop-only --keep-space
```

從輸出取得整數 `spaceId`，以它取代以下的 `SPACE_ID`。後續測試逐批共用該空間與預設頁面 `p1`，不要同時啟動多個 runner：

```bash
python3 tests/run-rwd.py --space SPACE_ID --suite required --protocol both --desktop-only
```

`required` 依序執行 `rwd`、`ui-scale`、`gameplay`、`account-gameplay`、`companion-commands` 的 HTTP／file 測試。批次執行會保留空間，遇錯即停。

依修改範圍再執行相關 suite，例如能力／裝備與倉庫：

```bash
python3 tests/run-rwd.py --space SPACE_ID --suite effect-details warehouse-list village-clan-warehouse --protocol both --desktop-only
```

`visual-*` 必須緊接同一空間、同一協定的對應行為 fixture，中間不可插入其他 suite，例如 `--suite effect-details visual-effect-details`。

| 參數 | 行為 |
| --- | --- |
| 預設輸出 | 報告／畫面寫入 `tmp/test-runs/`，不納入提交。 |
| `--record` | 明確寫入 `tests/artifacts/`，用於需保存於版本控制的驗收資料；本地整合測試也支援此參數。 |
| `--artifacts PATH` | runner 寫入指定目錄，相對路徑以專案根目錄為準；不能與 `--record` 同用。 |
| `--skip-screenshots` | 略過圖片擷取，繼續行為檢查；畫面須另行驗收。 |
| `--keep-space` | 單輪結束後保留空間；批次自動啟用。 |

全部驗收完成後，在 Ego 腳本中對該 TaskSpace 呼叫一次 `await task.finish({keep:[]})` 並等待完成。測試不能使用真實角色或 iCloud 存檔。HTTP／file、桌面橋接替身與公開網站資源比對，也不能當作桌面安裝版或 iCloud 同步實測。
