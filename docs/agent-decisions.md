# 已確認的產品決策

由 `AGENTS.md` 移出以減少每次載入的 token；內容為原文，修改對應功能前讀相關小節即可。

### 版面與隊伍

- 固定基底優先桌機與窄側欄；手機／平板僅在本輪已授權的可選「行動裝置版」範圍內調整與驗證，不擴大改造桌機版面。
- 三欄寬度可拖曳／鍵盤調整並記憶；桌機左欄至少 220px、右欄至少 300px。中欄保留原生戰鬥場景的可用寬度與 800×450 比例，不因側欄調整破壞冒險畫面。
- 三次選擇獨立：隊伍清單 **C「統一名牌」**、技能設定 **A「緊湊卡片」**、隊友裝備 **A「經典人形」**。外層 **A「倉庫系銀框」**採 `warehouse-frame-v1.webp` 48 fill／18px，一層邊框含紋理即可；標題直接置於框內配小飾紋，不再疊 `party-title-cartouche-v1.png` 或完整外框背景。隊伍／技能設定按鈕沿用 handler，以 `warehouse-row-v1.png` 做深色／金色紋理，220px 仍須完整單行；不改名牌／sprite／資源條。
- 名字不加底線；名牌名稱為 14px，職業與等級樣式一致；保留原 HP／MP／EXP 與寵物控制。
- 主角、隊友與寵物的暈眩等異常狀態放在名稱旁，過期即清除；不另占一列。長文字保留完整 title，不以縮小整張名牌解決擠壓。
- 隊友與寵物的倒地、復活倒數及操作須同列；寵物倒數整合進原卷軸按鈕，保留原 handler。須實測 220px 左欄，不能只檢查較寬側欄或只測傭兵。
- 左上資訊的等級／AC／MR 同列；設定頁查詢與小百科使用緊湊按鈕，保留查詢及另開頁面的操作。
- 用原版 sprite 與透明範圍裁切資訊，不拉伸或修改原圖；資料由 `scripts/update-party-portraits.py` 更新。
- 隊伍區利用左欄剩餘高度；內容放得下時不出現內部捲軸，超出時才捲動。
- 武器／防具／道具頁改用「整理背包」選單，保留分類／品質／名稱整理及取得物品時自動整理；移除左側舊按鈕與 `sortInventoryNow` 強制分類入口，不再恢復一鍵排列。整理模式與自動整理沿用角色偏好及原儲存流程，不連動自動販賣。切換分頁關閉選單；選單須容納完整 checkbox 標籤，不能只驗按鈕外框。

### 加掛選項與角色分頁

- 設定頁內設「一般設定／加掛版功能」tab；17 個可選開關預設全關，既有功能（含訓練、賽狗、自動購買）維持固定基底。`sellconfirm` 為可選，不能誤關基底功能。
- 偏好沿用 `lineage_optional_addons_v1`，本機跨角色共用；勾選僅改草稿，取消可還原。套用先完成角色／共用資料與帳本寫入，再儲存偏好、讀回確認並重載；寫入失敗或其他角色仍在遊玩時不重載。結算閘使用 `state.ff`／`catchupActive()`，不能用提示元素的 `getClientRects()`；透明提示仍有尺寸，會造成完成後永久誤擋。
- 「行動裝置版」單一開關涵蓋 11 個手機模組，不拆散暴露；本版整合放在 `addon-settings`、`addon-mobile-bridge`、`addon-optional-integration`，不修改鏡像原檔。
- 保留本版離線引擎與原生帳號搬移；不引入替代結算、全清式還原、身分重發、雲端轉移或分析追蹤。歷史僅記錄原生成功結算，每角色最近 5 筆。
- `SAVE_SLOT_MAX=16` 為資料上限；`visibleSaveSlotMax()` 為選角／招募可見上限。關閉只隱藏第 9～16 格，不能刪資料；身分／帳本掃描及帳號匯出始終涵蓋 16 格，schema 2 接受舊 schema 1 八格並補空。
- **角色分頁美術以原版一致為優先**：沿用 `public/assets/login/load.png` 的圓框與翼飾，CSS 遮掉原圖數字再疊頁碼；不將現代圓鈕或新生成的高解析金屬框蓋在舊雙頁框上。生成圖已否決，不恢復。
- 四頁裝飾寬為舞台 34%；頁碼採細長 `Times New Roman` 斜體、`scaleX(.92)`、`6.72cqw`（原 `5.6cqw`＋20%），保留暗金漸層／磨損／凹刻柔光，不把整組雕框一起放大。置中核對字形重心、圓孔及命中；字級與螢幕 rect 比較先乘 UI 縮放，翼飾加入後頁數用 `querySelectorAll('button')` 而非 `children.length`。
- 背包角標採 **B「右下雙行」**：暗金數量 `(N)` 在上、藍色 `+N` 在下；數量比原 responsive 字級小 **1pt＝4/3 CSS px**、色碼 `#a6894d`，不連帶縮小／調暗強化值。單件不顯數量、未強化不顯 `+0`；保留千分位、E／鎖定／廢品與快速強化。
- 創角必填「角色 ID」：沿用暱稱 1～12 字及字元規則，trim 後存 `player.name`、`renameCount=0`；驗證須在重置 player／寫存檔前擋下，不只停用按鈕。換職業／性別保留草稿，另開空格創角清空；舊未命名角色仍可載入，不重發角色身分。版面順序固定「配點 → Character Name 輸入列 → 確定／取消」，不把名稱放到按鈕下方。

### 裝置縮放

- UI 為 60～100%、每格 5%，80% 位於中央；初始值、提示與重設均為 80%。沿用 `lineage_ui_scale`；以 `lineage_ui_scale_80_v1` 做一次性裝置遷移。偏好寫入成功才寫完成標記；之後不得覆蓋使用者新選擇。
- 無效值回 80%，有效越界值限制在範圍內；寫入失敗保留當次畫面並提示，未完成的遷移下次重試。
- 縮放可用尺寸取 `document.documentElement.clientWidth/clientHeight`；桌機欄界用 `matchMedia` 與 CSS 斷點一致。勿以可能受橫向溢位影響的 `innerWidth` 判斷欄界，否則分隔線會攔住分頁。
- 螢幕座標轉 UI 座標沿用 `screenToUiPx`；尺寸持久保存值與 `getBoundingClientRect()` 比較前須換算縮放，不能直接比較不同單位。

### 能力提示、隊友浮窗與技能條件

- 浮窗出現在隊伍選單右側附近，可拖動；四邊與四角皆可縮放並記住尺寸。不透明度控制在設定頁；沿用 `lineage_party_window_v1`，不另造偏好格式。
- 總能力與 buff 加成同頁；數值如 `13（＋3）` 必須同一行。
- 主角及隊友能力提示須列出實際 Buff／裝備來源與差值；沿用 `partyBonusSnapshot` 在副本重算，不修改 live 角色、資源、裝備或倒數。
- 寵物能力用 `petDerive`／裝備／魅力／光環／狀態的原生欄位，顯示普攻骰值、傷害與命中加值、攻擊間隔、倍率及實有魔法技能；隱藏六屬性與無對應的主角爆擊／魔法欄，不用「—」填滿。倍率與目標減免另計；tooltip 取該欄 `data-ability-keys`，只在副本預覽，不改戰鬥公式。
- 數值懸浮採「一行一來源」，不列 0、不寫「小計」以外的計算註解：六屬性列 `初始點數`／`升級配點`／`萬能藥`（其他數值列 `基礎`），再列不為 0 的類別（`EFFECT_STAGES` 相鄰差值），全部相加等於總值。
- 每個來源在**自己類別的階段**移除比較（`abilitySourceDetails`），同類可加總；單一來源接在同列，多來源時類別數字後加「（小計）」並縮排列出。只在單項加總≠類別時加一行互斥／乘算提醒。來源名稱不含強化 `+N`。
- 顏色只分兩種：外加的所有類別與標題「（額外 +N）」統一用括號色（不利方向用紅）；萬能藥列及該屬性在能力表的總值改橙色（`data-panacea`），升級配點不另上色。不在括號內做多色分段（窄欄放不下）。
- 提示在效果到期後更新，來源重算按需執行，避免每 tick 全量運算。
- 主角與隊友裝備畫布下方顯示 `equipmentSummaryHtml`：防禦 AC 與生效套裝，每列單行省略並保留完整 title；隨 Buff 變動更新，高度變了才重排。
- 裝備物品提示只保留原生名稱、描述、能力、職業、重量、安定值與特效；已移除「自身加成」、「套裝效果」、「條件／觸發特效」三個附加區塊及尾端計算註解，不恢復已移除的產生函式。
- 畫布下方與狀態提示的套裝說明只列原生直接效果，不用 `DB.sets` 舊數值或屬性衍生差值。歐林西瑪＝「兩件套裝：六項屬性各＋1、AC－5、HP＋50」；命中、傷害、HP／MP 等衍生差值仍留在能力來源查詢，不改戰鬥公式。
- 裝備物品說明採原版「跟隨滑鼠」：游標右下方、`pointer-events:none`、不可移入。定時更新用最後指標座標；重找錨點只限同一裝備視窗／隊友浮窗（`#tab-equip` 底層清單有同 uid 元素，全頁搜尋會跳位）。
- 主角與隊友的能力說明也跟隨游標，靠邊翻轉並限制在視窗內；移出即關閉，live 更新不跳位或消失。鍵盤 focus 保留欄位下方定位，不讓滑鼠 focus 覆蓋游標座標。
- buff 圖示不直接顯示倒數；懸浮顯示秒數，接近到期閃爍並尊重 reduced-motion。
- 裝備分頁採原版人物與部位配置，保留 E／強化值／數量及原生懸浮資訊；不是清單或等寬方格陣列。
- 裝備資料與職業判定取被查看的隊友，不能誤用主角；浮窗唯讀，不可改隊友裝備。裝備框高度由浮窗外框扣除標題、分頁與 padding 決定；不要用內容自身高度回推，否則會逐次縮成細條。
- 裝備畫布依可用寬高等比縮放：寬度不足時格子照比例變小（以不破圖為優先），高度不足時縮到格子 50px 為止，再矮改為上下捲動；不以橫向捲軸掩蓋破圖；欄位數仍為原生 19／9。
- A 技能卡片的選單／門檻對齊；checkbox 等寬，依最長已學技能名決定最小格寬，不截斷長名稱。停止條件固定在轉換技能右邊；數值統一為 `HP≤30%`、`HP<63%`，不加「停技」「喝水」尾字。
- 保留「喝水條件」標題、門檻說明與原生 handler；不新增概念圖裡不存在的 MP 門檻或技能。
- `_hpSkillPct` 不只影響轉換：也影響龍騎士耗 HP 技、耗 HP 增益與立方和諧。 HP 低於或等於門檻就停止；0 關閉自訂門檻，但後三類保留至少 25% 的安全限制；普通治癒不受此門檻阻擋。
- 每隻出戰寵物的「喝水條件」放在隊伍技能分頁；只有寵物也可操作。沿用 `potPct`、0～95、0 關閉、實際 `HP≤門檻%` 與 `petMarkDirty`／`petRosterSave`。
- 寵物技能欄只隨名冊／名稱等結構變動重建，HP／MP 刷新不得打斷正在編輯的輸入；驗證儲存、名冊重載與整頁重載。

### DPS 與日誌

- 新建／載入角色在歡迎訊息後顯示最新系統日誌；背景分頁／其他視窗返回時也切 `sys`、解除系統捲動鎖並到底。`focus`／`visibilitychange` 去重；返回後使用者再切分頁，不由補跑完成回呼搶回。戰鬥日誌測試先明確切 `combat`。
- DPS 快照須保留原怪物物件，不能把槽位消失／瞬移／換怪當作 HP 歸零；已造成的傷害、真正溢殺與變身仍按原怪物掉血量計算。
- `_dpsSnap` 保留數值陣列供鏡像訓練模組使用，另附原物件 `targets`；修改須一起檢查 `threatCommitDiff` 的身分比對，避免新怪繼承假傷害／仇恨。
- DPS 名稱、計量條與數值須共用整張圖的欄寬（`audit-dps-chart`／subgrid），不能逐列獨立計算；每條底條起點與可用長度一致。名稱單行、有完整 title；窄欄不得讓名稱、條與數值互相蓋住。驗證桌機／窄螢幕及 75%／100% 縮放。
- 寵物以 UID 分別累積到 `_dps.pets` 並顯示名稱；保留 `_dps.pet` 合計。普攻、魔法、額外攻擊及 DoT 都須歸正確寵物，額外普攻不能被外層技能快照重算一次。

- 「施法」是 `combat-filter-pills` 中與玩家／傭兵並列的 **小 tab**，不是上層「戰鬥日誌／系統日誌」分頁。玩家與傭兵的施法動作都用 `data-src="cast"`；施法者身分保留在文字與 `data-cast-source`，不得讓玩家／傭兵開關連帶控制施法開關。

### 戰鬥、經驗與村莊增益

- 寵物與召喚物沿用原版選敵／攻擊邏輯；不要恢復指定目標、保護主人或新的指揮功能。寵物／召喚物只接受一般「加速術」；按受益者扣施法者 MP，不分享強力加速術或其他增益。

- 招募隊友保留來源 EXP，再投影未領取的帳本／outbox；按 UID 去重並核對角色身分。

- 同角色回村刷新保留 live buff 與剩餘時間；不可拿來源存檔的舊倒數覆蓋，也不可復活已過期的增益。

### 效能與線上人數

- 先區分首次載入、物品筆數、長時間累積及存檔停頓；用相同合成資料、圖／技能／負重／視窗比較，每組暖機後多次量測，不以搬檔或單次耗時宣稱改善 FPS。
- 倉庫超過 250 列採可視範圍更新，保留完整搜尋／數量／交易／雙側捲動與焦點；不要把 DOM 列數當總物品數。`whbatch` 開啟仍保留完整 DOM，確保原全選範圍，不直接虛擬化鏡像批次操作。
- `renderTabs` 依分頁失效；改數量不重建無關分頁，但要追查所有 consumer：快速強化標頭依賴道具頁卷軸，手機戰鬥狀態鏡射依賴隱藏的 `dt-buffs`。不能只按來源分頁可見性停止更新；鏡射適配放 `addon-mobile-bridge`，驗證新增／到期、手機／平板及桌機閒置，保留強制重繪、排序與加掛順序。
- 卡頓先量再改：先寫好門檻（例：1,000 件改一筆數量 ≥16ms 才做局部更新），再用戰鬥 60 秒 CPU profile 把長任務歸因到連續非 idle 樣本；Ego 擴充功能的 `content_script.js` 不屬於遊戲。未達門檻就記錄數據後不做。
- tick 內不可呼叫 `renderTabs(true)`：背包簽章依陣列順序，排序後用 `renderTabs()` 就會重建且併入 250ms 節流。`autoSortInventory` 已改；延後重建在 1,000 件仍約 55～63ms，要再降須先處理上述 consumer，不可直接只重建可見分頁。
- 不把 `index.html` 的 script 改為動態延後載入：`afk-pwa` 的 reconcileCode 以開頁時 DOM `script[src]` 為保留清單，之後插入的 script 會被清出程式快取、離線失效；攻城資料 eval 僅約 4～6ms，不值得。
- 能力預覽用 `effectPreviewActor`，不深複製整份背包與巢狀隊伍；唯讀背包仍供原公式查持有頭盔授技，會修改的裝備／技能／Buff 用副本。保留來源加總、到期更新及 live／儲存／亂數不變性。
- 功能未顯示先核對 URL、載入條件、遠端 commit 與 Pages 部署。`online-presence` 僅正式 origin／路徑進入角色後啟用，本機 HTTP／file 不加入公開房間；tracker 失敗顯示不可用，同瀏覽器多分頁合計一人，不傳角色或存檔。
- 效能回歸跑 `performance` 與 `ui-performance --soak-minutes 0` HTTP／file；長測另明傳時長，記錄硬體、快取、樣本數及來源 SHA。`--soak-minutes 0` 只驗短測；5／30 分鐘須依實際時間分別標示。rAF 未完成或受節流不能推算延遲／FPS；heap 不含圖片，GC 及量測成本須分開。影格／長任務紀錄固定容量，避免測試陣列自身增長污染長測；中止／縮時須明列。
- DOM 同步比較 live 值後才寫；CSSOM 會正規化色碼、URL 與小數百分比，快取須同時核對實際值，避免每 tick 重寫或忽略外部改動。能力總值更新保留內層加成節點、focus 與重配點草稿，內容／版寬變動才量尺寸。
- 登入首頁動畫與創角立繪是不同流程；保留原首幀，首頁可見才續載其餘影格。離開首頁或切背景須取消 rAF／排程並停止預載鏈，返回再續播；不靠每幀空轉判斷隱藏。
