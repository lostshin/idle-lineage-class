# 遊玩與存檔運作方式

這份說明讓你了解遊戲如何推進戰鬥、保存角色，以及重新開啟後恢復哪些資料。依據 2026-10-13 工作目錄中的原始碼，包含本輪尚未提交的共用設定改動。

核心戰鬥在瀏覽器的 JavaScript 中運算。網頁伺服器提供 HTML、程式與素材；查核到的角色存檔流程寫入本機儲存，沒有雲端帳號同步步驟。

## 開始遊玩

1. 開啟 `index.html`，或進入提供此專案的網站。
2. 按「開始遊戲」，進入角色選擇。共有八個存檔位，分成兩頁，每頁四格。
3. 選擇空格並按「創新角色」，完成職業與配點後開始；已有角色則按「進入遊戲」。
4. 進入遊戲後，選擇地區與狩獵地圖並按「出發」。地圖會檢查等級、任務、鑰匙等適用條件。
5. 在「設定 → 自動戰鬥」調整補血、技能、增益、補貨及迴避頭目。

新角色由 `startGame()` 建立：先重設角色與地圖物件，配發職業起始裝備與物品，再進入起始村莊、啟動計時器並立即存檔。已有角色由 `loadGame()` 恢復。

原始碼依據：[角色選擇與建立](../js/13-shop-save.js)、[地圖進入條件](../js/11-world-map.js)。

## 戰鬥如何持續進行

遊戲以三個記憶體物件保存執行中的狀態：

| 物件 | 主要內容 |
| --- | --- |
| `player` | 職業、能力、HP／MP、經驗、金幣、背包、裝備、技能、增益及角色設定 |
| `mapState` | 目前地圖、怪物、目標與出怪排程 |
| `state` | 是否正在遊玩、累計 tick、補跑與其他執行狀態 |

`startGameTimers()` 每 100 毫秒呼叫 `gameLoop()`。一個邏輯 tick 代表 0.1 秒，因此正常速度約為每秒十次。

`gameLoop()` 依實際經過時間決定要跑幾次 `tick()`。每個 tick 會推進狀態與冷卻、自然恢復、自動技能、藥水與增益、出怪、玩家攻擊和其他戰鬥行為。各行動仍受攻速、施法冷卻、HP／MP、負重及異常狀態限制。

怪物死亡後，`killMob()` 標記死亡並結算經驗、金幣與掉落；怪物格清理與目標重選另由死亡清算流程處理。角色變強、取得物品與消耗藥水，都先改變記憶體中的狀態，再於存檔時保存。

自動戰鬥從 `settings.get()` 讀取角色設定，設定面板關閉後仍會繼續運作。開啟設定面板本身不會暫停戰鬥。

原始碼依據：[狀態與計時器](../js/01-drops-config.js)、[遊戲主迴圈](../js/03-combat-core.js)、[自動行動與技能](../js/07-skills-cast.js)、[擊殺結算](../js/05-kill-progression.js)。

## 背景掛機與關閉遊戲

| 情況 | 目前行為 |
| --- | --- |
| 遊戲頁面在前景 | 由每 100 毫秒的主計時器推進 |
| 切換到其他分頁或縮小視窗，頁面仍存在 | Worker 每秒嘗試喚醒主迴圈；主迴圈依經過時間補跑 |
| 瀏覽器暫時凍結頁面後恢復 | 依最後一次執行時間，將尚未處理的時間排入補跑 |
| 真正關閉頁面，再重新開啟 | 讀取已保存進度，沒有關閉期間的離線收益結算 |
| 返回角色選擇 | 先要求存檔成功，再停止遊戲計時器 |

補跑逐 tick 執行相同的戰鬥邏輯，因此仍會消耗物品、觸發掉落或死亡。程式分批運算並讓出執行時間，減少長時間卡住畫面；補跑期間通常延後存檔，收尾時再處理。

Worker 和頁面能否持續執行，仍受瀏覽器凍結、丟棄分頁與裝置休眠影響。這是原始碼所提供的排程機制，不能據此保證背景永遠全速運作。

儲存庫仍有 `js/27-offline-rewards.js`，但目前 `index.html` 沒有載入它。判斷現行功能時，應以實際載入的程式為準。

原始碼依據：[背景心跳與恢復](../js/01-drops-config.js)、[補跑與收尾](../js/03-combat-core.js)、[目前載入清單](../index.html)。

## 存檔保存在哪裡

統一儲存介面是 `_lsGet()`、`_lsSet()`、`_lsRemove()`；初始化時依是否存在 `window.fableStore` 選擇後端。

| 執行環境 | 儲存介面 | 對你的影響 |
| --- | --- | --- |
| 網站或直接開啟 HTML，沒有桌面橋接 | 瀏覽器 `localStorage` | 角色存在目前瀏覽器的本機儲存中，程式沒有自動雲端同步 |
| 安裝版注入 `fableStore` | Host 提供的 `get`、`set`、`remove` 等方法 | JavaScript 把資料交給桌面儲存服務；實際檔案位置由 Host 決定 |

這份儲存庫沒有查找到桌面 Host／preload 實作，因此不能從這裡確認安裝版的確切存檔路徑。程式中的 Electron、WebView2 與檔案路徑註解，也不能代替對實際封裝的查核。

原始碼依據：[統一儲存層](../js/00-data.js)。

## 存檔內容與格式

每個角色使用 `lineage_idle_save_1` 到 `lineage_idle_save_8` 的獨立鍵。`saveStateJson()` 產生以下結構：

| 欄位 | 內容 |
| --- | --- |
| `v` | 存檔格式版本，目前 `SAVE_VERSION` 為 `2` |
| `p` | `player`，包含角色進度與 `player.config` |
| `ms` | `mapState` |
| `ticks` | 遊戲累計邏輯 tick |

保存前會清理不適合序列化的戰鬥參照；部分召喚物與城堡護衛實體是戰鬥暫存，不以目前實體快照保存。

寫入流程如下：

```text
目前角色與地圖狀態
  → saveStateJson()：序列化 JSON
  → _saveWrap()：加入完整性檢查格式
  → _lzSet()：選擇明文或壓縮寫入路徑
  → _lsSet()：交給 localStorage 或 fableStore
```

網頁格式使用 `SIG1:`，可用的桌面簽章服務使用 `SIG2:`。這些格式用於檢查內容是否一致，不會把 JSON 加密。網頁版 `SIG1` 的產生方法也在前端程式中，不能把它當成由可信伺服器驗證的防作弊機制。

網頁版先立即寫入帶完整性標記的內容，成功後再交給 Worker 壓縮成 `LZ1:` 格式。Worker 結果會比對版本與原始值，避免舊壓縮結果覆蓋較新存檔。若首次寫入失敗，會嘗試同步壓縮後寫入；桌面橋接則直接寫入未壓縮內容。

原始碼依據：[序列化與存檔](../js/13-shop-save.js)、[完整性格式與壓縮](../js/00-data.js)。

## 什麼時候存檔

| 時機 | 行為 |
| --- | --- |
| 建立新角色 | 完成初始化後立即存檔 |
| 遊戲執行期間 | 每五分鐘呼叫 `saveGame()` |
| 手動存檔 | 「設定 → 存檔管理 → 手動存檔」 |
| 特定重要操作 | 包含頭目擊殺、部分裝備／物品操作、任務與復活等流程 |
| 切到背景、離開或關閉頁面 | `visibilitychange`、`pagehide`、`beforeunload` 嘗試立即存檔 |
| 返回角色選擇 | 存檔成功才切換畫面並停止計時器 |
| 匯出目前角色 | 先要求存檔成功，再產生匯出檔 |

因此，畫面上的即時進度與最後成功寫入的進度可能不同。角色設定修改後立即生效，但要等遊戲存檔才持久保存；聲音與特效偏好則在修改時寫入各自儲存鍵。

`saveGame()` 遇到死亡、空角色、角色已刪除或存檔位換人等情況會拒絕寫入；背景補跑時可能先延後。角色存檔或寵物名冊寫入失敗時，它會回報失敗，設定面板也顯示「未儲存」。角色與名冊分別寫入，這個流程不是所有資料一起成功或一起回復的交易。

關頁事件是額外的存檔機會，不能保證瀏覽器被強制終止時一定執行。需要確定保存時，使用手動存檔並確認成功結果。

原始碼依據：[五分鐘計時器](../js/01-drops-config.js)、[存檔與關頁掛點](../js/13-shop-save.js)、[設定存檔動作](../js/settings-ui.js)。

## 重新開啟後如何恢復

`loadGame()` 依目前存檔位讀取內容，依序解壓、檢查完整性、解析 JSON，恢復角色、地圖資料與 tick 計數，再補齊舊檔缺值、處理遷移、重算能力、重繪介面並啟動計時器。

雖然保存了 `mapState`，目前讀檔流程仍會呼叫 `setMapSelectors(getHomeTown())` 與 `changeMap(true)`，把角色帶回家鄉村莊。你可以恢復角色進度，但不是從上一場戰鬥畫面的原樣快照繼續。

角色設定重新綁定到該角色的 `player.config`，補齊缺少的設定預設值，並保留未知欄位；讀檔時不會用上一個角色的控制項值重建設定。

原始碼依據：[讀檔流程](../js/13-shop-save.js)、[缺值補齊](../js/01-drops-config.js)、[角色設定綁定](../js/settings.js)。

## 角色以外的共用資料

| 資料 | 儲存方式 |
| --- | --- |
| 角色進度與自動戰鬥設定 | 各角色存檔中的 `p` 與 `p.config` |
| 倉庫 | `lineage_idle_warehouse`；經典模式使用 `_classic` 後綴 |
| 寵物名冊 | `fb5_pet_roster`；依模式使用對應後綴 |
| 血盟共用狀態 | `fb5_clan_state_v1` |
| 背景音樂、戰鬥音效 | `fb5_bgm`、`fb5_sfx` |
| 特效與傷害數字 | `lineage_vfx_off`、`lineage_vfx_num_off` |

這是主要資料的摘要，並非所有儲存鍵的完整清單。收藏、任務紀錄等子系統也有各自的保存方式。

## 備份與匯入

備份目前角色：

1. 在「設定 → 存檔管理」按「手動存檔」，確認成功。
2. 按「匯出目前角色」，選擇位置保存，或取得瀏覽器下載的 `.json` 檔。
3. 保留該檔，作為匯入時的來源。

還原備份：

1. 進入角色選擇，選擇空存檔位。
2. 按「匯入進度」，選取備份檔。
3. 若備份包含共用資料，依提示決定是否還原倉庫、寵物、龍之鑽石與血盟資料。
4. 匯入成功後選取該角色並進入遊戲。

匯入會拒絕直接覆蓋已有角色的格子，也會拒絕把相同身分的角色複製到另一格。若原角色仍存在，就不能把備份當作第二個同角色使用。還原共用資料會影響使用該共用資料的其他角色。

角色匯出包含角色資料及上述共用資料；傭兵引用會移除，寵物匯出副本設為未出戰。它不是所有裝置偏好與儲存鍵的完整備份。

網頁匯出與安裝版匯出有相容性界線：安裝版要求自己的簽章及專用容器，網頁版拒絕安裝版 `SIG2` 匯出。現行程式沒有提供兩種環境之間的角色轉換流程。

原始碼依據：[匯出與匯入](../js/13-shop-save.js)。

## 查核範圍

本次由主 agent 查核目前原始碼及既有測試報告，沒有修改遊戲程式，也沒有重新執行瀏覽器測試。既有 [HTTP 報告](../tests/artifacts/settings-report-http.json) 與 [file 報告](../tests/artifacts/settings-report-file.json) 各記錄 22 項通過，包含角色切換、存檔、匯出匯入、儲存失敗、設定狀態與桌面橋接替身。

實際桌面 Host 的檔案位置、原生寫入與簽章，以及裝置休眠或分頁被丟棄後的行為，未在本次實機驗證。
